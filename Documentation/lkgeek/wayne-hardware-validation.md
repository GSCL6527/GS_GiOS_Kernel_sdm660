## 本轮修复依据

内置 WLAN 驱动此前只创建控制字符设备，ROM 却尝试插入不存在的 wlan.ko。恢复 CONFIG_QCA_CLD_WLAN=y 时主动加载，保留模块构建的延迟控制方式与加载失败清理。旧内核原有主动加载行为。

相机 HAL 调试日志明确要求 CPP 实体类型 0x10f09，而实际实体类型统一为 0x20000，group_id 为 9。MSM_CAMERA_SUBDEV_BASE 为 0x10f00。在 Qualcomm 相机子设备注册前设置 function = BASE + group_id，恢复此 HAL 所需的枚举协议，仅作用于 camera_v2 注册路径。该项不是修改全局媒体枚举行为。需在新镜像验证传感器探测及前后摄，不能仅凭静态核查列为通过。

### 相机修复进一步核查

首次实体类型补丁使 HAL 开始传感器探测，但仍报告 power_setting size_up=0。进一步确认 Wayne defconfig 本来指定 MSMB_CAMERA_OSS=y，上游合并却删除了对应 Kconfig 和 Makefile 分流，构建时静默丢弃该选项并改用通用 camera_v2，造成整套 ABI 不匹配。最终方案恢复 OSS 选项、对应 Makefile 和 Kconfig 路由，移除临时通用实体类型补丁；改用仓库原有 camera_v2-oss 驱动和专用头文件。此版本已构建并实际运行；完整前后摄、录像和关闭压力测试仍待补齐。

## ROM 兼容设置

已在设备应用 `tools/wayne/rom-compat.sh apply` 对应设置：关闭跨窗口模糊，保留普通界面与动画；解除审计日志每秒 5 条的 ROM 限速。前者是已验证能消除严重模糊卡顿的兼容取舍，不能描述为保留完整模糊效果的渲染优化。后者依据 /system/etc/init/logd.rc 已有 persist.logd.audit.rate 接口；实机曾报告数千条 audit_lost。增加日志输出会增加存储和处理开销，环形缓冲与冷复位仍存在保存限制。

手机上脚本路径 /data/local/tmp/rom-compat.sh，root 执行 `sh /data/local/tmp/rom-compat.sh restore` 可恢复原来的模糊及日志限速；备份位于 /data/local/tmp/lkgeek-rom-compat。本轮原始模糊值为 0，日志限速属性为空（ROM 默认 5）。这部分设置无需修改 system/vendor。另有亮度转发修复修改 vendor 的专用 init 规则和新增适配脚本，详见 wayne-rom-display-compat.md。模糊设置曾被 ROM 在重启后重置，持久化仍待验收。

OSS 栈重新启用后，修复其 Makefile 使用相对源码头文件路径导致 O= 构建失败的问题，及 ISP vm_fault 回调类型与新工具链不匹配问题。
